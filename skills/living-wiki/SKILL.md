# Живая память: MEMORY.md + skills (skill v1)

Один вход — `AGENTS.md`, одно хранилище — `MEMORY.md`, один тип процедур — `skills/<имя>/SKILL.md`. Никакого графа и папок «на вырост». Версия одна — v1, окончательная.

Установка: если `MEMORY.md` нет, создай его с пустым скелетом (раздел 2 в `AGENTS.md`) и работай дальше. Если есть — сверь `rules_hash` в frontmatter `AGENTS.md`: не совпал, замени файл правил; `MEMORY.md` и `skills/` не трогай.

## Как устроена память

- `MEMORY.md` — плоский список коротких фактов, разделы: «О пользователе», «Проект и стек», «Решения», «Грабли», «Открытые вопросы».
- Одна строка — один факт, декларативно: «пользователь предпочитает короткие ответы», а не «всегда отвечай коротко».
- Дубликаты не дописываются: похожая строка заменяется или сливается.
- Противоречие не хранится двумя версиями: старая строка заменяется новой.
- Лимит файла — 6000 символов (5400 — начинай сжимать). Проверка: `wc -m MEMORY.md`.
- Догадка помечается `[вывод]`.

## Два слоя памяти

`MEMORY.md` — горячий слой (факты и строки-указатели, до 6000 символов), `memory/<тема>.md` — холодный слой (детали по областям: архитектура, контракты, схема БД, бизнес-правила). Один файл темы — до ~15 КБ, читается только когда тема всплыла; больше — разбей по подтемам.

## Когда не влезает

6000 — потолок горячего файла, а не знаний. Строгий порядок, стоп на первом шаге, который дал место:

1. вытеснить деталь в `memory/<тема>.md`, оставив в `MEMORY.md` строку-указатель;
2. слить дубликаты;
3. убрать переставшее действовать (решённые вопросы, починенные грабли, отменённые решения, устаревший стек);
4. сжать формулировки, выкинув примеры и обоснования;
5. не писать строку вообще, если она не изменит поведение в следующей сессии.

Жертвы — только строки и указатели; файлы тем целиком не режутся. Порядок жертв: «Открытые вопросы» → «Грабли» → «Решения» → «Проект и стек» → «О пользователе» (только слиянием, не удалением). Строки не обрезать, факты о пользователе молча не терять, параллельную копию памяти вместо `memory/` не заводить.

## Как устроены скилы

`skills/<имя>/SKILL.md` с frontmatter `name`, `description` («Use when …»), `updated`, и разделами «Когда применять», «Шаги», «Грабли», «Проверка».

- Создавай, когда процедура повторилась, оказалась неочевидной или пользователь сказал «запомни, как делать».
- После задачи, где скил пригодился, допиши строку о том, чего не хватало. Подвёл дважды — перепиши «Шаги» целиком.
- Скил длиннее 150 строк — детали в `<имя>/notes.md`.
- Индекса нет: список папок и есть индекс.

## Когда писать — сразу, без команды

Пиши в том же ответе, где факт выяснился. Не в конце сессии, не по слову «закончили», не по вопросу «записать?».

Перед завершением содержательного ответа молча проверь: новый факт о пользователе или проекте → `MEMORY.md`; принятое решение или причина бага → `MEMORY.md`; сложилась повторяемая процедура → скил; старая запись устарела → замени. Ничего нет — не пиши ничего. Выдумывать записи ради активности запрещено.

## Чистота

В корне проекта: файлы проекта + `AGENTS.md` + `MEMORY.md` (+ указатели инструментов). Второй памяти не заводить (`memory.md`, `notes.md`, `brain/`); найденную — перенести в `MEMORY.md` и удалить. Память — не журнал: только то, что действует сейчас.

## Версия

v1 — единственная и окончательная, без подверсий. Свежесть копии правил определяется `rules_hash` (`scripts/rules-hash.sh`), а не номером.
