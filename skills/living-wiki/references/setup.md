# Разовая настройка — установка и обновление версии

## Установка (структуры ещё нет)

Если папок `wiki/` и `self/` ещё нет в текущем проекте — создай:

```
<vault>/
  index.md
  log.md
  AGENTS.md                    — единственный полный источник правил для ЭТОГО проекта:
                                  копия файла AGENTS.md из корня этого репозитория
                                  (путь от этого файла: ../../../AGENTS.md), целиком,
                                  с тем же frontmatter bootstrap_version
  attachments/                 — локальные вложения (скриншоты ошибок, UI-багов, схемы)
    .gitkeep
  raw/
    processed/
      .gitkeep
  wiki/
  self/
    index.md
    Goals.md
    Habits.md
    Lessons-Learned.md         — активные уроки (LOD 1: строго до 150–200 строк)
    Skills.md                  — индекс скилов проекта
    skills/                    — скилы: self/skills/<имя>/SKILL.md
                                  (папка появляется с первым реальным скилом)
    Lessons/                   — архив уроков (LOD 2: срезы при превышении лимита)
      .gitkeep
    Reviews/
      .gitkeep
  journal/
    .gitkeep
  crm/
    .gitkeep
```

- `index.md` — оглавление верхнего уровня: ссылка на `[[self/index]]`, по ссылке на `index.md` каждой темы в `wiki/`, ссылка на сегодняшний `journal/`.
- `wiki/<тема>/index.md` — создавай подпапку и index только когда появилась первая реальная страница по теме, не заранее.
- `attachments/` — скриншоты ошибок, схемы и визуальные материалы к урокам. Чтобы личные скриншоты не утекли в git, добавь `attachments/*` (кроме `.gitkeep`) в `.gitignore`.
- `log.md` — только дописывание, одна строка на действие: `2026-09-12 14:02 — создан wiki/rag/index.md по материалам из raw/`.
- `attachments/`, `raw/`, `raw/processed/`, `journal/`, `crm/`, `self/Lessons/`, `self/Reviews/` — `.gitkeep` в пустых папках обязателен, иначе они пропадут при клонировании репозитория. Убирай его из папки только когда там появился первый настоящий файл.
- `self/skills/` — скилы проекта: одна папка на скил, `SKILL.md` внутри, индекс в `Skills.md`. Папку не создавай заранее — появляется вместе с первым скилом; формат и правило автообновления — `references/skills.md`, скелет — `templates/skill.md`.
- `AGENTS.md` проекта — не пересказывай своими словами и не копируй из `SKILL.md`: скопируй именно файл `AGENTS.md` из корня этого репозитория, он самодостаточен и рассчитан на любого агента, не только на Claude Code.
- Если в проекте будет использоваться больше одного агента/инструмента — см. `references/multi-agent.md`, прежде чем заводить файлы-указатели для остальных.

После создания коротко сообщи пользователю, где vault, и что его можно открыть в Obsidian как vault. Один раз добавь: будущие обновления плагина не приходят сами — включить auto-update можно в `/plugin` → Marketplaces → `living-wiki` → Enable auto-update, иначе обновлять вручную через `/plugin marketplace update living-wiki`.

## Обновление (структура уже есть)

Если `wiki/` и `self/` уже есть — тебя запустили повторно в уже работающем проекте (например, плагин обновился). Не выполняй установку заново и не пересоздавай ничего.

1. Найди в frontmatter `AGENTS.md` этого проекта поле `rules_hash`. Поля нет — копия старше v1: правила обновляются целиком.
2. Сверь его с `rules_hash` из frontmatter `AGENTS.md` в корне этого репозитория (тот же хэш руками пересчитывается `scripts/rules-hash.sh`).
3. Совпал — ничего не трогай, кроме короткого сообщения: «правила уже актуальны, изменений нет».
4. Отличается — обнови слой инструкций: скопируй `AGENTS.md` и папку `skills/living-wiki/` (сам `SKILL.md` + `references/`) в проект, новый `rules_hash` уже внутри скопированного файла. Допиши строку в `log.md` вида `<дата> — обновление правил v1 (rules_hash <старый> → <новый>)`. Если обновление вводит папки, которых раньше не было (`self/Lessons/`, `raw/processed/`, `self/skills/`) — создай только то, чего не хватает. Данные пользователя (`Goals.md`, `Habits.md`, `Lessons-Learned.md`, `journal/`, `wiki/`, `raw/`, `attachments/`, история `log.md`) не трогай никогда. После замены сверь, что список файлов в `wiki/`, `self/`, `journal/`, `raw/`, `attachments/` не изменился; если чего-то не хватает — это ошибка обновления, остановись и сразу скажи пользователю, что пропало.
5. Версии `v1.1` не существует и откатывать нечего: история старых копий — это git-история репозитория, а не отдельные релизы. Если пользователь просит «откатиться» — покажи ему `git log` и уточни, что именно он хочет вернуть.
