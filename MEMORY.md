# Память

## О пользователе
- Пользователь поставил задачу разработать новый формат долговременной памяти для ИИ-агентов с коэффициентом сжатия 200:1 и выше.

## Проект и стек
- Проект: ALMF (Agent Long-Term Memory Format) — сверхплотный бинарный контейнер и поисковый движок долговременной памяти агентов.
- Стек: Python 3.10+, Brotli/Deflate, аппаратный SimHash-64 (`.bit_count()`), FTS5, Living Wiki bridge.

## Решения
- Адаптивный мультимодальный роутер сжатия:
  - Логи и шаги отладки: сжатие 1:1000 – 1:5000 через извлечение инварианта `!INVARIANT: {problem}({root_cause}) -> {fix}`.
  - Архитектура и ADR: сжатие 1:100 – 1:300 через семантический DSL.
  - Исходный код: AST-скелеты сигнатур функций и типов без тел (1:20 – 1:50).
  - Точные данные (секреты, регулярки): lossless BlobVault с подстановкой указателя `@ptr(hash)`.
- Индексация: 64-битный SimHash с ограниченной max-heap кучей обеспечивает субмиллисекундный поиск на 10 000 элементах (0.461 мс).
- Рюкзачная контекстная оптимизация: жадный выбор фактов со строгим соблюдением инварианта $T_{\text{rendered}} \le B$.

## Грабли
- Жадная аллокация тысяч объектов `SimHashMatch` в цикле поиска раздувает задержку до 5 мс; лечится хранением легких кортежей в куче и аллокацией датаклассов только для финального среза `top_k`.
- Передача огромных строковых литералов в вызовах инструментов приводит к ошибкам TLS-стрима; генерация больших датасетов должна выполняться процедурно по алгоритмическим шаблонам с фиксированным сидом (`seed=42`).
