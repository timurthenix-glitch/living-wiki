# Changelog

`bootstrap_version` в `AGENTS.md` и `skills/living-wiki/SKILL.md` — версия схемы vault, оба файла обновляются синхронно и **точно** совпадают (это два формата одной и той же цифры: YAML frontmatter в skill-файле vs заголовок в AGENTS.md). `version` в `.claude-plugin/plugin.json` — версия самого пакета плагина, отдельный semver: он обязан быть **не меньше** `bootstrap_version`, но может уйти вперёд неё ради чисто упаковочных релизов (хуки, лицензия, примеры, CI), которые не меняют схему vault — см. раздел «Версионирование» в README.md. `scripts/check-version-sync.sh` (в CI) проверяет оба правила.

## Package v0.3.1 (bootstrap v0.3, experimental) — last build 2026-09-17

Схема vault меняется: `bootstrap_version` `v0.2` → `v0.3`. Самая дорогая и наименее надёжная часть цикла — раздел 4.6 «Полная уборка»: раз в 10–15 страниц агент вручную открывал и удерживал в контексте весь `wiki/`+`self/`, чтобы найти битые ссылки, сирот и разросшиеся страницы. Эта версия выносит механическую часть проверки в детерминированный скрипт — по тому же паттерну, что уже был у `check-review-due.sh`: скрипт только находит, решения (слить дубликат, добавить связь, разбить страницу) остаются за агентом.

- **Новый `hooks/vault-lint.sh`** — необязательный ускоритель для раздела 4.6 `AGENTS.md`/`SKILL.md`: сканирует `wiki/` и `self/` (без `journal/` и `self/Reviews/` — это датированные логи, не узлы графа) на битые `[[wikilinks]]`, страницы-сироты (<2 связей), разросшиеся страницы (раздел 5) и файлы, не упомянутые в `index.md` своей темы. По умолчанию молчит, если всё чисто; с флагом `--list` печатает построчный отчёт «файл → что не так», без содержимого файлов, — агент читает только этот отчёт и открывает точечно лишь перечисленные страницы, а не весь vault.
- Подключён вторым `SessionStart`-хуком в `hooks/hooks.json` рядом с `check-review-due.sh` — на чистом vault не стоит ни одного лишнего токена, drift ловится каждую сессию, а не только раз в 10–15 страниц.
- `AGENTS.md`/`SKILL.md`, раздел 4.6: формулировка «пройдись по всему `wiki/` и `self/`» заменена на «если доступен `hooks/vault-lint.sh` — работай по его отчёту; если нет (другой агент, без плагина) — вручную по-старому». Ручной способ остаётся задокументированным fallback — гарантия раздела 0/1 (`AGENTS.md` работает в любом агенте без инфраструктуры плагина) не нарушена.

## Package v0.3.0 (bootstrap v0.2, experimental) — 2026-09-17

Схема vault меняется: `bootstrap_version` `v0.1` → `v0.2`. Правила связывания страниц ужесточены на основе наблюдения, что страницы с одной случайной ссылкой («сироты») засоряют граф в Obsidian и дороже искать при будущих ответах из памяти, без пользы для связности мысли. Версия пакета поднята до `0.3.0` (было `0.2.0`) специально, а не оставлена как есть — иначе у уже установленных копий не появилось бы предложение обновиться (Claude Code сравнивает именно `version` из `plugin.json`, см. README).

- `AGENTS.md` / `skills/living-wiki/SKILL.md`, раздел 1: минимум связей на странице поднят с 1 до 2–3 содержательных — с явной оговоркой не притягивать ссылки ради количества (это то же выдумывание, только про структуру, а не про факты).
- Раздел 4.1 (Приём) / `references/intake.md`: связывание теперь двустороннее — агент явно ищет существующие релевантные страницы перед созданием новой и, где уместно, дописывает обратную ссылку в них, а не только форматирует ссылки «вперёд».
- Раздел 4.1: приём сырья из `raw/` теперь проактивно дробит несколько самостоятельных мыслей на отдельные смысловые страницы сразу, а не ждёт превышения лимита размера страницы (раздел 5) — раньше разбивка была только реактивной.
- Раздел 4.6 (Полная уборка): периодическая уборка теперь также ищет страницы с < 2 связей и либо добавляет реальную связь, либо оставляет как есть — без искусственного дотягивания до нормы.
- Новый пункт раздела 3 `AGENTS.md` / `references/intake.md`: одноразовая рекомендация настроить нативные Obsidian Color Groups (Settings → Graph view) по основному тегу страницы — Obsidian красит только узлы, не рёбра, поэтому тип связи читается по цвету её концов; чисто визуальная настройка, без сторонних плагинов и без расхода токенов.
- **Новая опция для тех, кто хочет остаться на старой схеме:** `.claude-plugin/marketplace.json` теперь перечисляет два плагина — `living-wiki` (эта версия, схема v0.2) и `living-wiki-legacy-v0.1` (зафиксирован на теге `living-wiki--v0.2.0`, последнем релизе ещё со схемой v0.1). Оба ставятся из одного и того же `/plugin marketplace add timurthenix-glitch/living-wiki` — версию выбирают отдельной командой `/plugin install <name>@living-wiki`. Это официально поддерживаемый способ параллельных версий в Claude Code (`source` плагина может указывать на свой git-ref) — не отдельная ветка/marketplace, как временно делалось на этапе эксперимента.
- **Фикс:** раздел 2.1 `AGENTS.md` (сравнение версий при апдейте уже существующего проекта) ссылался на устаревшее «сейчас — v0.1» вместо `v0.2` — не поменялось при бампе версии в этом же релизе. Если бы это не поправили, агент, обновляющий уже существующий vault, мог бы неверно определить, что новее.
- **Усилена гарантия сохранности данных при апдейте.** Раздел 1 `AGENTS.md`/`SKILL.md` явно называет это отдельным принципом (не только пунктом внутри раздела 2.1): апдейт `bootstrap_version` трогает только `AGENTS.md`/skill и файлы-указатели, никогда — `wiki/`, `self/`, `journal/`, `raw/`, `log.md`. Раздел 2.1/`references/setup.md` теперь также требует после замены файла сверить, что список файлов в этих папках не изменился, и остановиться с явным сообщением пользователю, если что-то пропало, а не тихо продолжать.

## Package v0.2.0 (bootstrap v0.1) — 2026-09-14

Пакетные и инфраструктурные улучшения — контракт `bootstrap_version` (`v0.1`) не менялся, схема vault и данные пользователя не затронуты. Версия пакета поднята намеренно отдельно от схемы (см. правило версионирования выше), чтобы у Claude Code был повод предложить обновление уже установленным копиям.

- `LICENSE` (MIT) + поле `license` в `.claude-plugin/plugin.json`.
- `description` в `skills/living-wiki/SKILL.md` дополнен явным «не использовать для»: техдокументация/API/архитектурные и командные wiki не должны триггерить этот скилл.
- Семь файлов-указателей (`.clinerules/`, `.cursor/rules/`, `.github/copilot-instructions.md`, `.junie/guidelines.md`, `.kiro/steering/`, `.qoder/rules/`, `.windsurf/rules/`) теперь генерируются из единого `templates/rule-pointer.md` через `scripts/sync-rule-pointers.sh`.
- CI (`.github/workflows/checks.yml`): `scripts/check-rule-pointers.sh` проверяет, что копии-указатели не разошлись с шаблоном; `scripts/check-version-sync.sh` проверяет соотношение версий; `scripts/check-json-valid.sh` проверяет, что `plugin.json`/`marketplace.json`/`hooks/hooks.json` — валидный JSON. Строгую проверку самой схемы манифеста (`claude plugin validate --strict`) в CI не подключали намеренно — это отдельный тяжёлый CLI ради двух маленьких файлов, что противоречит собственному принципу проекта «не добавляй инфраструктуру сверх того, что решает задачу» (раздел 1 `AGENTS.md`); вместо этого она — рекомендованный ручной шаг перед релизом (см. README).
- `hooks/hooks.json` + `hooks/check-review-due.sh` — необязательный `SessionStart`-хук: читает реальные файлы `self/Reviews/` (без отдельного состояния) и, если Weekly/Monthly обзор просрочен, добавляет напоминание в контекст сессии. Разделы 4.7/6.4 `AGENTS.md` остаются обязательными для агента независимо от того, сработал ли хук.
- `examples/demo-vault/` — заполненный пример структуры (wiki/self/journal/Reviews) для наглядности формата.
- README дополнен коротким англоязычным абзацем в начале (что это и как поставить). Полный перевод `AGENTS.md`/`SKILL.md`/`references/*` на английский осознанно не делаем: вторая языковая копия — это второй источник правды для инструкций, которые агент реально исполняет, а именно это правило 1 `AGENTS.md` запрещает («Один источник правды»). Единственное поле, которое реально влияет на срабатывание скилла в Claude Code (`description` в frontmatter `SKILL.md`), и так уже на английском.
- Инвариант версий пересмотрен: раньше `check-version-sync.sh` требовал точного равенства `plugin.json` и `bootstrap_version`, из-за чего пакетный релиз без изменения схемы (как этот) физически нельзя было выпустить, не нарушив CI. Теперь требование — `plugin.json >= bootstrap_version`.

## v0.1 — 2026-09-13

Первая версия.

- Базовая структура: `wiki/<тема>/`, `self/` (Goals, Habits, Lessons-Learned, Skills, Reviews), `journal/`, `raw/`, `crm/`.
- Автоматизация саморазвития: триггеры на сигнальные фразы, стрики привычек, обнаружение повторов и противоречий, еженедельные/ежемесячные обзоры по календарю.
- Правила против частых поломок: единственный источник правды, запрет на схему «про запас», обязательные `.gitkeep`, explicit-failing автоматизация, пороги на размер страницы.
- Версионирование самого бутстрапа: `bootstrap_version` в frontmatter `AGENTS.md`, раздел 2.1 — обновление при повторном запуске без потери данных пользователя.
- Упаковка: `AGENTS.md` — универсальный fallback для любого агента; `skills/living-wiki/SKILL.md` + `.claude-plugin/` — устанавливаемый плагин для Claude Code; короткие файлы-указатели для Cursor/Windsurf/Cline/Copilot/Qoder/Kiro/Junie.
- Экономия контекста для Claude Code: `SKILL.md` разделён на компактное ядро (всегда нужное — принципы, постоянный цикл, триггеры саморазвития) и `skills/living-wiki/references/*.md` (разовая настройка, обзоры, приём данных, мультиагентность — читаются агентом только когда реально нужны). `AGENTS.md` избавлен от дублирующихся формулировок (было отдельным разделом 8, повторявшим раздел 1, и повтором про «другие агенты» внутри раздела 2). Поведение и структура вики не изменились, `bootstrap_version` не поднимался.
