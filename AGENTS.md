# ЖИВАЯ ПАМЯТЬ — один файл памяти и скилы, как у Hermes

**Всё, что нужно, — этот файл.** Одна версия (v1), одно хранилище (`MEMORY.md`), один тип процедур (`skills/`). Ни графа, ни вики из страниц, ни дневников, ни папок «на вырост». Если правила здесь нет — не выдумывай структуру.

## 1. Из чего состоит проект

```
AGENTS.md              — правила (этот файл). Меняется редко, читается всегда.
MEMORY.md              — горячий слой: факты и строки-указатели, до 6000 символов.
memory/<тема>.md       — холодный слой: детали по темам, читаются только когда тема всплыла.
skills/<имя>/SKILL.md  — процедуры: как делать то, что повторяется.
```

Больше ничего не заводи: ни `wiki/`, ни `journal/`, ни `raw/`, ни `notes/`, ни `brain/`. `memory/` — не вторая память, а её холодная часть: у каждой темы один файл, без копий.

## 2. Установка (в новом проекте)

1. Скопируй этот файл в корень проекта.
2. Создай `MEMORY.md` — пустой скелет, без выдуманных фактов:

```markdown
# Память

## О пользователе

## Проект и стек

## Решения

## Грабли

## Открытые вопросы
```

3. Папки `memory/` и `skills/` не создавай заранее: `memory/` появляется с первой темой, `skills/` — с первым скилом.

Дальше работай по разделам 3–7 в каждом сообщении.

## 3. Формат памяти

- Одна строка — один факт. Коротко: `- Пользователь предпочитает короткие ответы без преамбул.`
- Декларативно, а не приказом: «пользователь предпочитает X» — верно, «всегда делай X» — нет (это правило, а не факт).
- Дата в скобках только если факт стареет: `(2026-10)`. Дат в заголовках разделов нет.
- Догадку помечай: `- [вывод] Бэкенд, скорее всего, на .NET — по стек-трейсу.`
- Дубликат не дописывается: нашёл похожую строку — замени или слей в одну.
- Противоречие не живёт двумя строками: старая заменяется новой, при желании с пометкой «было: …».
- Лимит — **6000 символов на файл**: 5400 (90%) — сигнал начинать сжатие, 6000 — потолок, выше файл не выходит никогда. Проверка одной командой: `wc -m MEMORY.md`.

### 3.1. Переполнение: сначала вытесняй в темы, потом сжимай

6000 — потолок **горячего** файла, а не потолок знаний проекта. Порядок строго такой, стоп на первом шаге, который дал место:

1. **Вытесни деталь в тему.** Всё, что длиннее одной строки и относится к одной области (архитектура, API-контракты, схема БД, бизнес-правила, деплой, история решений), уезжает в `memory/<тема>.md` целиком и без потерь, а в `MEMORY.md` остаётся строка-указатель: `- Архитектура и слои — memory/architecture.md`.
2. **Слей дубликаты** и близкие по смыслу строки в одну.
3. **Убери переставшее действовать**: решённые «Открытые вопросы», починенные «Грабли», отменённые «Решения», устаревшие части стека.
4. **Сожми формулировки**: выкинь примеры и обоснования, оставь факт.
5. **Не пиши новую строку**, если она не меняет твоё поведение в следующей сессии.

Жертвы касаются только строк и указателей. Файлы тем не режутся: устаревшую тему обновляют или удаляют целиком вместе с указателем, если её содержание стало неверным.

Порядок жертв в горячем файле: «Открытые вопросы» → «Грабли» → «Решения» → «Проект и стек» → «О пользователе». Последний раздел чистится только слиянием, никогда удалением.

Запрещено: обрезать строки на полуслове, молча терять факт о пользователе, заводить параллельную копию памяти вместо `memory/`. Освобождал место — делай вытеснение и запись одним проходом, чтобы файл ни на миг не остался сверх лимита.

### 3.2. Как читать холодный слой

Тема всплыла в работе — открой `memory/<тема>.md` и читай его, а не все файлы подряд. Один файл темы — до ~15 КБ (примерно 300 строк); больше — разбей на подтемы и оставь в родительском ссылки. Нет файла темы — значит деталей ещё нет, не выдумывай их.

## 4. Когда писать — сразу, не по команде

Пиши в том же ответе, где факт выяснился. Не в конце сессии, не по слову «закончили», не по вопросу «записать?».

- Пользователь сказал о себе, своих целях, привычках, ограничениях, предпочтениях → `MEMORY.md`, раздел «О пользователе».
- Принято решение по проекту, стек или архитектура → «Решения».
- Что-то сломалось и ты понял причину → «Грабли»: симптом, причина, как чинить.
- Появился вопрос, который надо решить позже → «Открытые вопросы»; решили — строку удали.
- Знание объёмнее одной строки (архитектура, контракты, схема БД, бизнес-правила) → `memory/<тема>.md`, в `MEMORY.md` только строка-указатель (раздел 3.1).
- Процедура повторилась дважды, или на её выяснение ушло больше нескольких шагов, или пользователь сказал «запомни, как делать» → скил (раздел 5).

Проверка на шум: факт, который пригодится в следующей сессии через месяц, — записывай; разовое состояние текущей задачи — нет.

## 5. Скилы

Живут в `skills/<имя>/SKILL.md`, формат:

```markdown
---
name: <короткое-имя-латиницей>
description: Use when <триггер>. <что делает, одной строкой>.
updated: <YYYY-MM-DD>
---

# <Название>

## Когда применять
## Шаги
## Грабли
## Проверка
```

- Создавай скил, когда процедура реально повторилась или оказалась неочевидной, а не «на будущее».
- После задачи, где скил пригодился, допиши одной строкой то, чего не хватало. Подвёл дважды — перепиши раздел «Шаги» целиком, не латай третий раз.
- Скил длиннее 150 строк — вынеси детали в файл рядом (`<имя>/notes.md`), в шагах оставь ссылку.
- Индекса нет: `ls skills/` и есть индекс.

## 6. Аудит ответа — сам, каждый раз

Перед тем как закончить содержательный ответ, молча пройди четыре вопроса:

1. Появился факт о пользователе или проекте? → `MEMORY.md`.
2. Принято решение или найдена причина бага? → `MEMORY.md`.
3. Сложилась процедура, которую придётся повторять? → скил.
4. Предыдущая запись устарела или неверна? → замени её.

Ничего не появилось — не пиши ничего: выдумывать записи ради активности запрещено. Разрешения не спрашивай. Пользователь не должен говорить «запиши» и не должен подводить итог вместо тебя.

## 7. Чистота

- В корне — только файлы проекта плюс `AGENTS.md`, `MEMORY.md` и файлы-указатели для инструментов. Дампы и скриншоты — туда, где им место по правилам самого проекта.
- Один источник правды: `MEMORY.md` + `memory/<тема>.md` — это одна память, а не две. Параллельные копии (`notes/`, `brain/`, второй `memory.md`) запрещены: найденную — перенеси и удали.
- Память — не журнал: истории «что делали вчера» в ней нет, только то, что действует сейчас.

## 8. Версия

Версия одна — **v1**, окончательная: подверсий и минорных номеров нет, любое улучшение вносится прямо в v1. Устарела ли копия правил в проекте, решает `rules_hash` во frontmatter (`scripts/rules-hash.sh`): не совпал — замени `AGENTS.md` на актуальный; `MEMORY.md` и `skills/` при этом не трогай.

## 9. Несколько агентов

Полный текст правил — только здесь. Для инструментов, которые не читают `AGENTS.md` сами (Cursor, Windsurf, Cline, Copilot, Antigravity, Kiro, Junie), положи рядом короткий указатель из `templates/rule-pointer.md`. Память у всех одна — `MEMORY.md`.
